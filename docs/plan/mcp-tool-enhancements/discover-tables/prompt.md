# Discover tables / describe table MCP tools — prompt

> Wraps the already-working `scripts/discover_athena_tables.py`/`run_table_ddl_export.py` CLI logic as `discover_tables`/`describe_table` MCP tools.

Read `CONTEXT.md` and state `CONTEXT.md ✓` before anything else. Then read `tasks.md`, find the first unchecked `- [ ]`, and do **only** that task. Read that task's full spec in
`stories.md` (same task id) before writing any code. One task per session. Complete it fully. Stop.

## Why this story exists

`astro-events-household-report`'s onboarding (`ASTRO-3`, in `oasis-athena-mcp`'s original `docs/plans/athena-mcp-server/tasks.md`) found that none of MTN's `AthenaQuery` subclasses
applied to Astro's schema, and required *manually* running `SHOW TABLES`/`SHOW CREATE TABLE` to discover Astro's actual table shapes before any registered query could be written.
That manual discovery work is exactly what `scripts/discover_athena_tables.py` and `scripts/run_table_ddl_export.py` already automate — but only as standalone CLI scripts a
developer runs by hand, not as MCP tools an agent can call mid-investigation. This story closes that gap.

## Scope guard

- In bounds: `src/athena_mcp/server.py` (new tool registrations), `src/athena_mcp/query_tools.py` (adapters), reusing the existing logic in `scripts/discover_athena_tables.py` and
  `scripts/run_table_ddl_export.py` rather than duplicating it.
- Out of bounds: changing the CLI scripts' own argparse-based entry points (they stay as-is for direct terminal use; this story adds a second, MCP-facing way to call the same
  underlying logic) and any project-specific table knowledge (`knowledge/<project>-athena-<database>-tables.md` docs stay generated by hand per `docs/table-ddl-knowledge-guide.md`,
  not auto-written by the new tools).
- Changes runtime behavior: yes, adds 2 new MCP tools; no changes to the 4 existing tools' contracts.

## Session-start load hints

- `scripts/discover_athena_tables.py`, `scripts/athena_cli_common.py`, `scripts/run_table_ddl_export.py` — the logic being wrapped.
- `docs/table-ddl-knowledge-guide.md` — the existing manual workflow this story makes available as MCP tools too (not a replacement for the knowledge-doc generation step).
- `src/athena_mcp/query_tools.py` — the adapter-layer pattern to follow (thin wrapper over `athena_runner`, unit-testable with a fake `AwsClientFactory`).

## Task overview

- **DISC-1** — Extract `discover_athena_tables.py`'s core "list tables in a database" logic into a function `athena_runner`/`athena_mcp` can both call, if not already separated
  from its argparse `main()`.
- **DISC-2** — Add `discover_tables(project, database=None)` MCP tool (`server.py` + `query_tools.py`), returning table names.
- **DISC-3** — Add `describe_table(project, database, table)` MCP tool, returning the table's DDL (via `run_table_ddl_export.py`'s DDL-fetch logic).
- **DISC-4** — Document both tools in `docs/mcp-server-setup.md`'s tool list.

## Definition of done

Both tools are registered, tested (mocked-boto3, no live AWS), documented, and pass `make test`/`make lint` alongside the existing 101-test suite.

## Perspectives not covered

This story does not add a `--dry-run`/cost-preview step before `describe_table`'s `SHOW CREATE TABLE` call — `SHOW CREATE TABLE`/`SHOW TABLES` scan no data (metadata-only), so
`estimate-cost` (a separate story) is not a prerequisite here.
